# Règle vampire SKYFORGE

## Statut

Règle validée par Fabien pour le bloc `10.1 - RACES WEREBEASTS VAMPIRES` et pour toutes les reprises futures du modpack.

Cette règle doit être lue avant toute proposition de mod vampire, de refonte vampirique, d'addon de confort vampire ou de patch lié aux mécaniques vampires.

## Règle vampire SKYFORGE validée

Fabien ne prévoit pas de jouer vampire.

Conséquence :

- ne plus ajouter de mods orientés principalement PJ vampire ;
- privilégier uniquement les mods utiles aux NPC vampires ou utiles à la fois au PJ et aux NPC ;
- éviter les addons de feeding, progression, pouvoirs ou confort vampire purement joueur ;
- garder `Sacrosanct` comme base déjà validée, car présent dans Nefaram et Nolvus Awakening ;
- ne pas empiler d'addons vampire sans bénéfice NPC clair.

## Interprétation pratique pour SKYFORGE

Lorsqu'un mod vampire est proposé, il faut d'abord répondre à cette question :

> Le mod apporte-t-il un bénéfice clair aux NPC vampires ou à l'écosystème vampires du monde, sans être principalement un confort de joueur vampire ?

Si la réponse est non, le mod doit être évité ou différé.

Si la réponse est oui, le mod peut être audité prudemment, mais il ne doit pas être ajouté automatiquement.

## Mods différés / évités

Les mods suivants sont à éviter ou à différer sauf décision explicite contraire de Fabien :

- `Vampire Feeding Tweaks` ;
- `Better Vampires` ;
- `Scion` ;
- `Sacrilege` ;
- `Vampire Lords Can Fly` ;
- addons de feeding orientés joueur ;
- addons de progression vampire orientés joueur ;
- addons de pouvoirs ou confort vampire purement joueur.

## Cas particulier — Sacrosanct

`Sacrosanct` reste accepté comme base vampire SKYFORGE, car :

- il est présent dans Nefaram ;
- il est présent dans Nolvus Awakening ;
- il constitue une base connue et déjà validée pour la cohérence du futur bloc vampires.

Cette validation ne signifie pas qu'il faut empiler tous ses addons ou extensions.

## Règle de reprise pour l'intendant

À chaque reprise du bloc `10.1 - RACES WEREBEASTS VAMPIRES`, l'intendant doit appliquer cette règle avant toute proposition.

Priorité :

1. éviter les mods PJ vampire purs ;
2. conserver une base vampire cohérente ;
3. favoriser les améliorations de NPC vampires, ennemis, comportements, équilibrage ou cohérence monde ;
4. ne pas ajouter d'addons vampire par automatisme ;
5. demander validation si un mod est ambigu.

## Statut documentaire

Cette règle est une décision structurante permanente tant que Fabien ne la modifie pas explicitement.
